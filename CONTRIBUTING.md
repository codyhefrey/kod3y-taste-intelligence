# Contributing to kod3y-taste-intelligence

Thank you for helping improve this public project.

## Getting started
1. Read the README, LICENSE and SECURITY.md where available.
2. Search existing issues and choose a small, clearly scoped task, ideally labeled `good first issue`.
3. Discuss major changes in an issue before implementing them.
4. Fork the repository, create a feature branch, and open a pull request against `main`.
5. Explain what changed, why, how it was tested, and any security or privacy implications.
6. Wait for maintainer review. Contributions are not automatically accepted or merged.

## Quality and safety
- Include tests for functional changes; run the repository's documented checks where available.
- Do not commit credentials, API keys, tokens, personal data, confidential documents, or proprietary enterprise code.
- Use synthetic data and safe defensive examples only. Do not include live malware, exploit payloads, or unauthorized access techniques.
- Report security vulnerabilities privately to maintainers rather than opening public exploit reports.
- Respect third-party licenses and intellectual property. By submitting a contribution you agree it is yours to submit under the repository's existing license, if any; do not assume a license where none exists.
- Maintainers may reject changes that weaken authentication, privacy, tenant isolation, auditability, or safety.

## Scope
This repository is the public/community edition only. Private enterprise implementations, infrastructure, credentials, and commercial intellectual property are out of scope. Do not copy code or data from private repositories.

## Review
Pull requests should pass applicable automated checks and receive maintainer approval before merging. Repository owners must configure GitHub branch protection or rulesets separately to enforce this policy.
